# Phase 4 — UI Design Contract

> Visual and interaction source of truth for the Arabic missing-route recovery page, local favicon, and the no-visible-regression boundary around search metadata and discovery output. Generated by gsd-ui-researcher for verification by gsd-ui-checker.

---

## Phase Scope and Visual Change Budget

Phase 4 adds only two intentionally visible outcomes:

1. A quiet Arabic 404 page rendered inside the existing shared site shell
2. A local cream-and-green SVG favicon visible in browser chrome

All existing homepage, section, article, author, header, prose, media, link, and focus surfaces inherit the approved Phase 3 contract unchanged. Metadata, canonicals, social tags, sitemap output, robots output, and origin validation are document-head, build, or crawler concerns; they must not add, remove, reorder, restyle, or shift visible body content.

Expected browser-chrome changes are limited to each route's maintained Arabic document title and the local favicon. No new page-body branding, navigation, badge, social preview, status panel, or SEO copy becomes visible.

**Sources:** `04-SPEC.md` requirements 1–6 and acceptance criteria; `04-CONTEXT.md` D-01–D-19; inherited `03-UI-SPEC.md`; verified current surface in `03-VERIFICATION.md`; current `SiteLayout.astro`.

## Design Direction

**Direction:** inherited quiet editorial minimalism.

- Reuse the current warm canvas, single centered reading column, Arabic system typography, underlined green links, and structural border treatment.
- Make the missing-route page look like an ordinary short editorial page, not a marketing interstitial.
- Give the error one balanced heading, one readable sentence, and one clear page-specific action.
- Add no card, illustration, icon, search box, suggested content, status code display, animation, transition, gradient, shadow, rounded panel, or client behavior.
- Treat the favicon as a small replaceable technical browser asset, not as a final owner-approved logo.

The selected Baseline UI guidance contributes only hierarchy, readable body copy, existing-theme reuse, no unrequested animation, and one clear empty/error-state action. Its generic Tailwind and React-component recommendations do not apply: this repository is locked to Astro, semantic HTML, and native CSS.

## Spacing Scale

Use the exact inherited Phase 3 scale. All new spacing values must come from this table.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px (`0.25rem`) | Tight inline separation only |
| sm | 8px (`0.5rem`) | Compact text relationships |
| md | 16px (`1rem`) | Mobile inline page padding; 404 heading-to-message gap |
| lg | 24px (`1.5rem`) | Desktop inline page padding; 404 message-to-action gap |
| xl | 32px (`2rem`) | Mobile main block padding |
| 2xl | 48px (`3rem`) | Reserved inherited major breaks; not required by the 404 |
| 3xl | 64px (`4rem`) | Desktop main block padding |

Exceptions:

- The header home link and the standalone 404 recovery link each expose at least a `44px` target in both axes. The `44px` minimum is an accessibility target, not a new spacing token.
- Borders remain `1px`; focus outlines and hover underline emphasis remain `3px`. These are strokes, not spacing values.
- Do not add intermediate spacing values, fixed block heights, or viewport-height centering.

### 404 spacing application

- Reuse the shared shell's `16px` inline padding below `48rem` and `24px` inline padding at and above `48rem`.
- Reuse `32px` main block padding below `48rem` and `64px` at and above `48rem`.
- The 404 content starts at the normal top of `main`; do not vertically center it in the viewport.
- Set the `h1` to message separation to exactly `16px` and the message to recovery-link separation to exactly `24px` after normalizing element margins.
- Keep the content start-aligned. Do not wrap it in a padded box or introduce a second inner content measure.
- Use logical properties only: `margin-block`, `padding-inline`, `padding-block`, `min-inline-size`, and `text-align: start`.

## Typography

Preserve exactly the four inherited sizes and two inherited weights. Phase 4 introduces no new size or weight.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 18px (`1.125rem`) | 400 | 1.9 |
| Label | 14px (`0.875rem`) | 700 | 1.6 |
| Heading | 24px (`1.5rem`) | 700 | 1.4 |
| Display | 32px (`2rem`) | 700 | 1.3 |

Application rules:

- `الصفحة غير موجودة` is the only 404 `h1`; it uses Display size, weight 700, line-height 1.3, and `text-wrap: balance`.
- `تعذر العثور على الصفحة المطلوبة.` and `العودة إلى الصفحة الرئيسية` use Body size, weight 400, and line-height 1.9.
- The inherited shared header link remains Body size at weight 700 and must not compete with the page heading.
- Keep `letter-spacing: normal`, `font-synthesis: none`, start alignment, Arabic joining, punctuation, and diacritics.
- Do not truncate, clamp, justify, uppercase, track, or split Arabic copy into character-level spans.
- No hidden typographic element, visible `404` numeral, English fallback heading, or decorative glyph may be introduced.

## Search Identity Without Visible Page Regression

### Page-title composition

The document title is browser/search identity, not a new body heading. Use the locked patterns exactly:

| Page family | Document title |
|-------------|----------------|
| Homepage | `مدونة أحمد المنجاوي` |
| Section | `${section.label} | مدونة أحمد المنجاوي` |
| Article | `${article.data.title} | مدونة أحمد المنجاوي` |
| Author | `عن أحمد المنجاوي | مدونة أحمد المنجاوي` |
| 404 | `الصفحة غير موجودة | مدونة أحمد المنجاوي` |

Descriptions reuse maintained visible facts: homepage introduction, section registry description, article frontmatter description, and author-page explanatory paragraph. The 404 description is exactly `تعذر العثور على الصفحة المطلوبة.`. Do not create a visible SEO subtitle, metadata preview, keyword row, social card, or parallel copy registry.

### Body invariance contract

For the eight verified indexable Phase 3 routes:

- Preserve the complete `<body>` landmark order, visible text, headings, lists, links, article facts, references, and media controls.
- Preserve exactly one visible `h1`; metadata must never be rendered as hidden or visible duplicate content.
- Preserve current computed font family, four-size scale, two weights, palette, `70ch` measure, paddings, borders, link underlines, focus outline, and the single `48rem` padding breakpoint.
- Do not add an SEO component wrapper around body content if it changes selector scope, margins, layout, or accessibility semantics.
- Do not fetch a remote image, font, social asset, or runtime metadata source. Head additions must cause no content layout shift.
- The favicon may appear in browser chrome only. Do not add it as a logo or image inside the header or main content.

The expected body screenshot difference for every existing route is zero pixels at the same browser, viewport, font availability, and content revision. If screenshot tooling is nondeterministic, DOM order, visible text, computed tokens, box positions, and document width must still compare equal before and after the metadata change.

### Indexing-state contract

- Indexable pages emit one title, one description, one self-canonical, and accurate text-only social metadata; they do not render an explicit visible indexing state.
- The 404 emits `noindex,follow`, has no canonical, is absent from sitemap output, and emits no Open Graph or Twitter share identity.
- Do not show `noindex`, canonical URLs, sitemap state, crawler policy, launch origin, or build validation messages in the public body.
- Robots and sitemap endpoints are machine-readable files, not styled HTML surfaces and not navigation destinations.

## Arabic 404 Surface Contract

### Route and document behavior

- A representative unknown path returns HTTP `404`, not a soft-404 `200` and not a redirect.
- Render the shared `SiteLayout.astro` shell with `<html lang="ar" dir="rtl">`, UTF-8, viewport metadata, the inherited one-link header, and one `main`.
- The page works as complete static HTML with JavaScript disabled and with third-party requests blocked.
- The route is absent from sitemap output and does not appear in the ordinary discovery graph.

### Required DOM and visible order

1. Shared `header` with `مدونة أحمد المنجاوي` linking to `/`
2. One `main`
3. One `h1`: `الصفحة غير موجودة`
4. One paragraph: `تعذر العثور على الصفحة المطلوبة.`
5. One page-specific recovery anchor: `العودة إلى الصفحة الرئيسية` linking to `/`

The `main` contains exactly one interactive element: the recovery anchor. The header's site-name home anchor remains part of the inherited shell, so the full document has exactly two anchors and both resolve to `/`. No search field, section list, suggestion, retry control, back-history button, illustration, icon, image, code block, technical URL, or JavaScript event handler is allowed.

### Visual anatomy

- The page background, main width, header rule, typography, and link styling are identical to existing pages.
- The `h1`, sentence, and action form one short start-aligned text stack on the ordinary canvas.
- The recovery action is an ordinary underlined link, not a filled button or campaign CTA. It may use `inline-flex` solely to provide its `44px` minimum block target.
- There is no dedicated error color. The error is communicated by the heading and sentence, not by red styling or an icon.
- The 404 must remain recognizably part of the site when CSS is unavailable through document order, Arabic text, heading semantics, and native anchors.

## Interaction, Focus, and No-JavaScript Contract

- Use native same-tab anchors only. Do not add `target`, click interception, `role="link"`, positive `tabindex`, history manipulation, custom keyboard handling, prefetch UI, or a client router.
- Tab order is the inherited header home link followed by the 404 recovery link. Enter activates either anchor natively.
- Both focused links show `outline: 3px solid #166534` with `outline-offset: 3px` on `:focus-visible`; no parent clips the outline.
- All text links remain visibly underlined. Hover changes only underline thickness to `3px`; it must not move content or rely on color alone.
- The recovery link exposes a minimum `44px` target in both axes while retaining its ordinary text-link appearance.
- There is no animation, transition, motion, hover reveal, tooltip, loading state, disabled state, or asynchronous error state.
- With JavaScript disabled, the missing-route response, Arabic explanation, and both home paths remain present and operable.
- With CSS unavailable, the landmark/heading/paragraph/link order remains coherent and complete.

## Responsive, Zoom, and Reflow Contract

- Support the continuous range from `320px` through `1440px`; the only breakpoint remains `48rem` and changes shared padding only.
- Keep one column, the same DOM order, and the same semantic hierarchy at every width. Do not introduce a grid, panel, side rail, horizontal scroller, or viewport-height centering.
- Header and main align to the same centered `70ch` maximum measure.
- At `320`, `390`, `768`, `1024`, and `1440` CSS pixels, the heading, sentence, and action wrap naturally with no overlap, clipping, truncation, or fixed-height crop.
- At `200%` zoom, all 404 content and both links remain visible, readable, and keyboard-operable without two-dimensional scrolling.
- Require `document.documentElement.scrollWidth <= document.documentElement.clientWidth`; never use global `overflow-x: hidden` to conceal a defect.
- Preserve `min-inline-size: 0` on relevant shared children. Do not display the unknown path, so a long hostile or percent-encoded path cannot force visible horizontal overflow.
- Phase 4 automated evidence may use a clearly labelled emulated scale/reflow check. Native browser-chrome `200%` production certification remains Phase 6 scope and must not be claimed early.

## RTL, Semantics, and Accessibility Contract

- The 404 document root is exactly Arabic/RTL: `<html lang="ar" dir="rtl">`.
- Use native `header`, `main`, `h1`, `p`, and `a`. Add no ARIA where native semantics already express the page.
- The page has exactly one `main`, exactly one `h1`, no skipped heading hierarchy, and no landmark added solely for styling.
- The two links expose their visible Arabic text as their accessible names. Do not override them with English or redundant `aria-label` values.
- Use `text-align: start` and logical CSS properties. Add no physical `left`/`right` layout rules and no page-level LTR override.
- No raw URL, Latin identifier, or mixed-direction technical value is visible on the 404. If diagnostics are added in development tooling, they must not enter the public document.
- Preserve current measured color contrast and visible underline/focus distinctions.
- Automated accessibility checks on the 404 must report zero serious or critical violations; manual checks must confirm landmarks, one H1, Arabic names, native tab order, visible focus, contrast, 320px reflow, and no keyboard trap.

## Local Favicon Contract

- Provide one local SVG favicon and reference the same asset from every emitted HTML document, including the 404.
- Use one `<link rel="icon" type="image/svg+xml" href="/favicon.svg">` per document. The request returns `200` with an SVG image content type and no redirect or remote dependency.
- Use a square `viewBox` and simple geometric open-page shapes only. The visible palette is cream `#FFFDF8` fill with green `#166534` stroke.
- Keep the silhouette legible at `16×16`, `32×32`, and high-density browser-tab sizes. Strokes must not disappear at 16px and shapes must remain inside the viewBox.
- Include no text glyph, Arabic letter, embedded font, raster image, data URI, script, animation, filter, gradient, shadow, remote reference, owner portrait, or YouTube mark.
- Do not add multiple theme variants, apple-touch assets, a web-app manifest, or a social-sharing image in this phase.
- Do not describe the favicon as an approved logo. It is a replaceable technical asset aligned with the current palette.

Favicon verification is semantic and visual: parse the SVG for a finite viewBox and allowed local geometry/colors, request it successfully, confirm every page references the same root-relative URL exactly once, and inspect rasterized 16px/32px captures for recognizable unclipped open-page geometry.

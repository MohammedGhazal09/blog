# Walking Skeleton — مدونة أحمد المنجاوي

**Phase:** 1
**Generated:** 2026-08-26

## Capability Proven End-to-End

> The owner can edit a validated Arabic Markdown or approved MDX article, preview it locally at its stable explicit Arabic route, and build static output in which drafts have no public path.

## Architectural Decisions

| Decision | Choice | Rationale |
|---|---|---|
| Framework | Astro 7.2.7 with static output | It renders file-authored content to crawlable HTML without a browser runtime or server adapter. |
| Build runtime | Node 24.19.0 LTS with npm 11.17.0 | These exact versions are locked and support Astro 7 plus Node's built-in TypeScript test runner. |
| Data layer | Git-authored Markdown/MDX through one Astro `articles` collection | Files are the source of truth; one schema and one query boundary prevent parallel content models. |
| Identity | Typed section/author registries plus one pure article-path helper | Stable ASCII keys reference truthful registry facts while explicit Arabic slugs determine `/{section}/{article}/`. |
| Validation boundary | Raw-source MDX preflight, collection schema, pure semantic rules, then collection-wide collision validation | Invalid content fails before route generation and downstream code consumes trusted typed records. |
| Auth | None | There is no account, CMS, editorial login, or request-time authorization requirement. |
| Database | None | The repository content files and registries are the complete persistence model. |
| Backend/API | None | Preview and production output are generated by Astro from local files; no mutation or request-time data exists. |
| Deployment proof | Documented `npm run dev` plus `npm run verify` and portable `dist/` output | Phase 1 proves the local/static pipeline without inventing a production origin or hosting target. |
| Directory layout | `src/content`, `src/config`, `src/lib`, `src/components`, `src/pages`, and `tests` | Each build-time responsibility has one direct home without feature-framework scaffolding. |

## Stack Touched in Phase 1

- [x] Project scaffold — exact framework, build scripts, diagnostics, and Node test runner
- [x] Routing — one final Arabic article route family
- [x] Data read — one mixed Markdown/MDX collection reads Git-authored records
- [x] Data write — editing the source Markdown/MDX file is the deliberate persistence operation
- [x] UI — semantic, visually unstyled Arabic proof HTML rendered from the article record
- [x] Local run/deployment proof — `npm run dev` and `npm run verify` exercise the complete static pipeline
- [x] Database/auth/API — intentionally absent because no Phase 1 capability crosses those boundaries

## Out of Scope (Deferred to Later Slices)

- Finished article layout, typography, accessibility treatment, and YouTube player — Phase 2
- Homepage, section indexes, About page, and reviewed launch articles — Phase 3
- Canonicals, social metadata, sitemap, robots directives, and public 404 — Phase 4
- Production origin, Cloudflare deployment, Search Console, and analytics — Phase 5
- Production crawl and Core Web Vitals verification — Phase 6
- CMS, database, authentication, search, community features, AI generation, transcript import, and automatic URL redirects — excluded from the release scope

## Subsequent Slice Plan

Each later phase adds one vertical slice without renegotiating the static content, registry, validation, and identity boundaries:

- Phase 2: One complete accessible Arabic article-to-YouTube reader journey
- Phase 3: Real reviewed content, homepage discovery, three section indexes, and author context
- Phase 4: Consistent metadata, canonical identity, sitemap/robots policy, and Arabic 404 behavior
- Phase 5: Canonical static deployment plus privacy-conscious discovery and outbound-link measurement
- Phase 6: Production crawl, Arabic presentation, link, Core Web Vitals, and iframe-loading verification

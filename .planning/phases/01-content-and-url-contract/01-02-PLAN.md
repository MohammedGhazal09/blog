</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Repository article/registry input → build validation | Git-reviewed author input can contain accidental malformed or unsafe facts. |
| Raw Markdown/MDX source → Astro compilation | MDX supports ESM and JSX, so policy checks must run before compilation. |
| Validated complete collection → public/preview query | Draft filtering or collision checks in the wrong order can publish hidden content. |
| npm registry/lockfile → local and CI build | Package identity/version drift can alter privileged build behavior. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-01 | Spoofing | Arabic section/article slugs | mitigate | Plan 01's shared canonical-slug assertion rejects non-NFC and control/format/bidi characters before paths. |
| T-02 | Spoofing / Tampering | Complete article path | mitigate | Plan 01 checks every complete path before visibility selection and reports both owners. |
| T-03 | Tampering / Information Disclosure / Elevation | MDX import/export | mitigate | `assertAllowedMdxSource` rejects ESM before compiler evaluation and articles cannot import dependencies. |
| T-04 | Tampering | Raw script/iframe or unknown JSX | mitigate | The same preflight rejects these tags/names against the one central allowlist before compilation. |
| T-05 | Denial of Service | Malformed source/frontmatter | mitigate | Policy and schema failures identify source plus rule; invalid strings remain isolated in native tests. |
| T-06 | Information Disclosure | Draft enumeration | mitigate | Existing public query filters before routes and explicit preview query fails outside development. |
| T-01-SC | Tampering | npm packages and lockfile | mitigate | No new package is added; the exact audited lockfile from Plan 01 remains authoritative. |

The preflight is intentionally bounded to trusted Git-reviewed authoring and is not a hostile-input sandbox.
</threat_model>

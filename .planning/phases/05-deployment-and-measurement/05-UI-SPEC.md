# Phase 5 — UI Design Contract

> Visual and interaction source of truth for preserving the approved Arabic/RTL site while adding invisible, production-only aggregate measurement. Generated by gsd-ui-researcher for verification by gsd-ui-checker.

---

## Phase Scope and Visual Change Budget

Phase 5 has a **zero-visible-change budget**. It adds no reader-facing surface, copy, state, control, consent banner, analytics notice, measurement indicator, deployment status, or Search Console UI.

The only permitted runtime addition is one non-rendering Plausible loader in the shared document head during the explicit `launch-readiness` build. It may create a production analytics network request, but it must create no body node, focus target, accessible object, reserved space, paint, animation, layout shift, or input handler owned by project code.

All homepage, section, article, author, 404, header, prose, media, link, favicon, focus, responsive, and no-JavaScript surfaces inherit the approved Phase 4 contract unchanged. The expected body screenshot difference on every existing route is zero pixels under controlled conditions.

**Sources:** `05-SPEC.md` requirements 1–6 and boundaries; `05-CONTEXT.md` D-01–D-19; approved `04-UI-SPEC.md`; current `SiteLayout.astro`; current `YouTubePlayer.astro`.

---

## Design Direction

**Direction:** preserve the existing quiet Arabic editorial interface exactly.

- Keep the warm canvas, one centered reading column, Arabic system typography, native landmarks, underlined green links, intent-gated video region, and permanent direct YouTube action.
- Treat deployment, Search Console, pageview measurement, and outbound-event reporting as operational concerns outside the reader interface.
- Add analytics only in the document head, only in launch-readiness output, and only as non-rendering deferred script markup.
- A slow, blocked, unavailable, or misconfigured analytics service must be visually indistinguishable from a successful analytics load.
- The direct YouTube link remains the product action. Measurement observes it automatically; measurement never becomes part of its label, layout, focus behavior, or activation logic.

The UI Skills Core Web Vitals guidance is applied narrowly: do not claim field performance without production evidence, and permit no render-blocking script, layout shift, or client-rendered content dependency. Core Web Vitals certification remains Phase 6 scope.

## Production-Only Measurement Contract

### Shared head boundary

- `SiteLayout.astro` remains the sole document-head integration point.
- Launch-readiness output contains exactly one maintained Plausible automatic-outbound loader per HTML document.
- Ordinary development and deterministic local production output contain no Plausible script, analytics markup, or analytics network request.
- The loader derives its public hostname from the already validated `Astro.site`; there is no page-level analytics prop, second domain input, visible host string, or reader-selectable state.
- Preserve deferred/non-render-blocking loading. Article content, navigation, and direct links are present in static HTML before and without the script.
- The script must not write visible nodes, inject CSS, reserve dimensions, move focus, announce status, alter document language/direction, or delay access to content.

### Outbound action boundary

- The only reportable reader action is activation of the existing permanent anchor whose destination is the generated `https://www.youtube.com/watch?v=…` URL.
- The report is an automatic outbound-link click. It is never named or interpreted as a play, video view, watch, watch-time event, completion, or iframe interaction.
- Preserve the exact Arabic accessible name `مشاهدة الفيديو على يوتيوب`, same-tab behavior, ordinary HTTPS `href`, DOM position outside the replaceable player region, and existing visual treatment.
- Add no `onclick`, project click listener, custom event call, tracking wrapper, bespoke data attribute, loading state, disabled state, navigation delay, confirmation, or duplicate anchor.
- The `تشغيل الفيديو هنا` button and the generated privacy-enhanced iframe are not outbound-link measurement targets.
- One physical direct-link activation produces at most one project-wired outbound attempt. Vendor receipt and dashboard reporting require real external evidence and cannot be inferred from a local interception.

### Failure behavior

- If the analytics request is blocked, offline, timed out, rejected, or unavailable, the page remains visually and semantically identical.
- Navigation to YouTube must not wait for analytics, retry analytics, display failure, or require JavaScript.
- No analytics failure reaches the existing player error paragraph; player failure and measurement failure are separate concerns.
- No service response may inject English reader-facing content or an accessible announcement.

## Interaction, Focus, and No-JavaScript Contract

- Preserve the existing native tab order, same-tab anchors, buttons, iframe focus behavior, and `:focus-visible` treatment.
- The direct YouTube anchor remains keyboard-operable with Enter and exposes `outline: 3px solid #166534` with `outline-offset: 3px` through the inherited focus rule.
- Hover changes only the established visual treatment; analytics adds no hover, active, visited, pending, or tracked state.
- Do not intercept navigation, call `preventDefault`, add a timeout, replace the anchor, synthesize a click, or introduce a keyboard handler.
- With JavaScript disabled, all Arabic body content, navigation, player privacy explanation, and permanent direct YouTube links remain complete and usable. No analytics request is expected.
- With the analytics vendor blocked, the same body and interaction contract remains complete.
- With CSS unavailable, analytics adds no text or control to the coherent native document order.

## Responsive, Zoom, RTL, and Accessibility Contract

- Preserve `<html lang="ar" dir="rtl">` on every public document.
- Preserve one centered `70ch` column, start alignment, logical CSS properties, and the single `48rem` padding breakpoint across `320px`–`1440px`.
- At `320`, `390`, `768`, `1024`, and `1440` CSS pixels, body text, controls, and links retain their approved order and dimensions with no new overflow, clipping, overlap, or truncation.
- At `200%` zoom, content and controls retain the approved reflow and keyboard behavior. Phase 5 must not claim native production zoom certification without the required evidence.
- Require `document.documentElement.scrollWidth <= document.documentElement.clientWidth`; never conceal a regression with global overflow clipping.
- Analytics adds no landmark, heading, live region, focus target, name, role, description, status, or DOM order change.
- Existing visible Arabic labels remain the complete accessible names. Do not append hidden tracking or English service text.
- Automated accessibility checks on representative launch output must retain zero serious or critical findings, while DOM and computed-style comparison must prove body invariance.

## Performance and Visual Stability Contract

- The analytics loader is deferred and non-render-blocking. It must not become a dependency for static content, styles, navigation, the player activation control, or the permanent direct link.
- No analytics code may synchronously mutate the body, measure layout, insert an overlay, or reserve visual space.
- Initial page layout and the intent-gated YouTube region remain dimensionally identical before, during, and after analytics loading.
- No eager YouTube iframe or new YouTube request is permitted. Measurement of the permanent outbound anchor does not change the existing player privacy boundary.
- Controlled tests may prove absence of new layout shift and project wiring, but they must not claim good production LCP, INP, CLS, Core Web Vitals, or field improvement. Those require Phase 6 production evidence.

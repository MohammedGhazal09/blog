<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Git-tracked Markdown/MDX + internal review JSON → static build | Local files are trusted inputs only after existing article validation plus strict exact-revision approval checks. |
| Filesystem path/JSON bytes → approval validator | Paths and JSON are untrusted enough to require containment, strict fields, real dates, literals, and digest comparison. |
| Development preview → production output | Draft proof records may be served directly only by explicit development mode and must never enter production routes or discovery. |
| Structural build → launch decision | A green ordinary build proves structure, not a truthful launch corpus; only the distinct readiness mode evaluates section coverage. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Tampering | Article/source digest | mitigate | Hash exact raw bytes with Node SHA-256 and reject stale sidecars before public selection. |
| T-03-02 | Tampering / Repudiation | Sidecar JSON and dates | mitigate | Strict root/field/literal/date/source/article validation with article-specific diagnostics; human authenticity remains repository-process evidence. |
| T-03-03 | Elevation of privilege | Missing approval path | mitigate | Every draft:false entry passes through central fail-closed approval validation; drafts alone bypass I/O. |
| T-03-04 | Information integrity | Phase 2 proof fixtures | mitigate | Set both proofs draft:true, use development routes only, and assert production route/content absence. |
| T-03-05 | Spoofing | Launch-ready status | mitigate | Separate nonzero mode, aggregate every missing section, and test that the failure is not a warning or missing script. |
| T-03-06 | Information disclosure | Reviewer identities/sidecars | mitigate | Approval function returns no sidecar; routes never import it; scan built HTML/DOM for fields and values. |
| T-03-07 | Spoofing / Repudiation | Human truth judgments | transfer | Automation records exact-byte human assertions but cannot certify identity, substance, religious accuracy, reference adequacy, or video match; Plan 03-04 blocks on real evidence. |
| T-03-SC | Tampering | Package supply chain | accept | No install or dependency change occurs; Node built-ins and existing pinned packages are sufficient. |

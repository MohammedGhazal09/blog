## Phase Scope and Truth Boundary

Phase 3 adds the smallest complete static discovery graph around the verified Phase 2 article reader:

1. A shared header containing only the site name linked to `/`
2. A homepage with one introduction and the three registered sections in registry order
3. One registry-derived index for each registered section
4. Section and author links in every public article fact list
5. One truthful author page at `/عن-أحمد-المنجاوي/`

All navigation is static HTML. The visual language remains a calm, text-first Arabic editorial surface. Discovery pages are lists, not cards, feeds, dashboards, or promotional landing pages.

This contract defines structure and truthful generic interface copy. Biography, expertise, affiliation, credentials, social profiles, channel ownership, reviewer identities, and approvals must not be invented. Optional author facts are omitted as complete units until supplied. Public article routes and discovery entries use validated source records, explicit draft state, and launch section coverage; the three AI-assisted launch articles disclose their production method and no-transcript status.

Final page titles, meta descriptions, canonicals, social cards, sitemap, robots, favicon, Arabic 404 behavior, analytics, hosting, and production certification remain outside Phase 3.

**Sources:** `03-SPEC.md` requirements 1–8; `03-CONTEXT.md` D-01–D-19; `ROADMAP.md` Phase 3; `REQUIREMENTS.md` `SITE-03`–`SITE-05` and `CONT-01`–`CONT-03`.

## Design Direction

**Direction:** quiet editorial minimalism.

- Preserve Phase 2's verified warm monochrome palette, Arabic system-font stack, typographic hierarchy, spacing scale, focus treatment, and `70ch` reading measure.
- Use hierarchy, whitespace, underlined links, and restrained structural rules. New discovery surfaces remain flat on the page canvas.
- Keep the site header deliberately small. It establishes identity and a reliable home path; contextual links provide the rest of the graph.
- Treat the homepage and section indexes as clean bibliographic lists. They must not resemble a card grid or marketing feed.
- Introduce no decorative or client-side behavior. There is no animation, transition, loading skeleton, hover lift, or runtime state management.

The selected UI Skills minimalist guidance contributes only warm monochrome, typographic contrast, flat structure, and restrained visuals. Its bento grids, imagery, gradients, webfonts, icons, shadows, pastel tags, and motion guidance are incompatible with locked project decisions and are excluded.

## Spacing Scale

Use the verified Phase 2 scale without extension.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px (`0.25rem`) | Tight inline gaps between fact labels and values |
| sm | 8px (`0.5rem`) | Heading-to-supporting-copy gaps and compact metadata gaps |
| md | 16px (`1rem`) | Mobile inline page padding, default prose rhythm, control padding |
| lg | 24px (`1.5rem`) | Desktop inline page padding and list-item block padding |
| xl | 32px (`2rem`) | Main section separation and mobile page block padding |
| 2xl | 48px (`3rem`) | Major page-content breaks where needed |
| 3xl | 64px (`4rem`) | Desktop main block padding |

Exceptions:

- Standalone navigation controls have a minimum `44px` target in both axes. Inline prose links and linked headings retain the native inline-link target-size exception.
- Borders are `1px`; a secondary control border may be `2px`; focus outlines and hover underline emphasis are `3px`. These are strokes, not spacing tokens.
- Do not introduce intermediate layout values. Use relative-unit equivalents in CSS.

### Layout application

- Below `48rem`, header and main use `16px` inline padding. Main uses `32px` block padding.
- At `48rem` and above, header and main use `24px` inline padding. Main uses `64px` block padding.
- Header inner content and main content are centered with `margin-inline: auto`, `min-inline-size: 0`, and `max-inline-size: 70ch`.
- The header home link has at least `44px` block size and uses the normal content column; the header is not a large hero band.
- Homepage section items and section-index article items use `24px` block padding with a `1px` structural divider between adjacent items. Do not wrap items in raised or rounded containers.
- Use `32px` between the page heading/introduction and the primary list, and `32px` between the heading and the first author-page fact/purpose block.
- Use logical properties exclusively for layout: `padding-inline`, `padding-block`, `margin-inline`, `margin-block`, `border-block`, `border-inline-start`, `inset-inline`, and `text-align: start`.

## Typography

Use exactly the four verified sizes and two verified weights. Do not introduce one-off site-header, list, or author-page sizes.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 18px (`1.125rem`) | 400 | 1.9 |
| Label | 14px (`0.875rem`) | 700 | 1.6 |
| Heading | 24px (`1.5rem`) | 700 | 1.4 |
| Display | 32px (`2rem`) | 700 | 1.3 |

Application rules:

- Each page has exactly one `h1` at Display size. On the homepage it is `أقسام المدونة`; section indexes use the registry section label; the author page uses `عن أحمد المنجاوي`; article pages keep the article title.
- Homepage section titles and section-index article titles are `h2` at Heading size, with the descriptive link inside the heading.
- The shared site-name home link uses Body size at weight 700. It is never larger than a page `h1`.
- Descriptions, introductions, author-purpose copy, and link labels use Body. Publication dates and article fact labels use Label.
- Use `text-wrap: balance` on headings only. Descriptions, dates, titles, and labels must wrap naturally and must never be truncated or line-clamped.
- Keep all text start-aligned and never justified. Preserve `letter-spacing: normal`, `font-synthesis: none`, Arabic joining, and diacritics.
- Use `overflow-wrap: anywhere` only for unbroken dynamic fragments, URLs, identifiers, and explicitly mixed-direction values. Do not hide overflow.
- Underlines remain visible on every text link, use font-derived thickness/position where supported, and skip ink.

**Evidence inherited:** Phase 2's post-fix review verified 14/18/24/32px, weights 400/700, the system Arabic stack, `1.9` body leading, and the `70ch` measure at 24/24 overall.

## Shared Shell and Link Graph

### Document shell

- Every emitted page starts with `<html lang="ar" dir="rtl">`, UTF-8 metadata, and the viewport declaration.
- Use one shared `header` followed by one `main`. Add no global footer, sidebar, search, menu, breadcrumbs, or repeated section navigation.
- The header contains exactly one visible link: `مدونة أحمد المنجاوي` → `/`. It is a normal same-tab anchor available before JavaScript and does not carry an icon.
- The main content is page-specific and begins with one `h1`.
- Do not add a skip link while the repeated header contains only this one home link. If later phases add a repeated navigation block, that later shared layout owns `تجاوز إلى المحتوى`.

### Required crawlable graph

## Surface Contracts

### Homepage `/`

Required document order:

1. Shared site-name header
2. `main`
3. One `h1`: `أقسام المدونة`
4. One concise introduction: `مقالات عربية في الردود والشبهات والقضايا العامة والعلوم الشرعية، مرتبطة بالمحتوى الموافق لها على يوتيوب.`
5. One semantic list containing every registry section exactly once in ascending `order`

Each section list item contains an `h2` with the registry label as the link, followed by its registry description. Current required order and copy are:

1. `الردود والشبهات` — `ردود موثقة على الشبهات الفكرية والدينية.`
2. `القضايا العامة` — `مقالات وتعليقات في القضايا العامة ذات الاهتمام المشترك.`
3. `القسم العلمي` — `دروس مرتبة في العلوم الشرعية والمعارف الإسلامية.`

The `القسم العلمي` description must remain registry-derived and must not be paraphrased as natural science. The homepage contains no latest-content feed, featured item, image, thumbnail, metric, count, promotion, carousel, CTA panel, or author biography.

### Registry-derived section index `/{section.slug}/`

Required document order:

1. Shared site-name header
2. `main`
3. One `h1` using the registry label
4. The registry description
5. One semantic article list, or the development-only empty-state sentence

For a populated index, each public article appears exactly once as one `li`. Each item contains:

1. `h2 > a` using the exact article title and stable route
2. The maintained article `description`
3. `<time datetime="YYYY-MM-DD">` rendered as `نُشر في: {التاريخ العربي الطويل}`

Sort by `publishedAt` descending. For equal dates, sort by stable article slug ascending. The list uses public articles only; it must never contain a draft, proof record, duplicate entry, hidden article, reviewer identity, approval badge, YouTube thumbnail, or section label repeated as decoration.

During local development only, a registered section with no previewable/public articles renders the exact sentence `لا توجد مقالات منشورة في هذا القسم بعد.` in the list position. Keep the section route and registry description visible. Do not hide the section or show an empty card/illustration. A production launch with any empty primary section fails readiness; the empty sentence is not a way to pass launch acceptance.

### Updated article context

Preserve the Phase 2 article anatomy, order, media behavior, and copy. Change only these fact values into contextual links:

- `القسم:` remains plain label text; the registry section name becomes a normal underlined link to its section root.
- `الكاتب:` remains plain label text; `أحمد المنجاوي` becomes a normal underlined link to `/عن-أحمد-المنجاوي/`.

Do not make the entire fact row clickable. Do not add breadcrumbs, a back button, a section menu, reviewer badge, expertise label, related articles, sharing actions, or approval language. The linked fact values inherit the article link/focus treatment and wrap without forcing horizontal overflow.

### Author page `/عن-أحمد-المنجاوي/`

Required document order:

1. Shared site-name header
2. `main`
3. One `h1`: `عن أحمد المنجاوي`
4. One publication-purpose paragraph: `تنشر المدونة مقالات عربية في الردود والشبهات والقضايا العامة والعلوم الشرعية، وتربط كل مقال بالمحتوى الموافق له على يوتيوب.`
5. Any owner-supplied and approved optional facts, each rendered only when present in the authoritative profile input
6. One same-tab home link: `العودة إلى الصفحة الرئيسية`

The `h1` is the only currently safe personal identification beyond the registered name. The generic purpose paragraph describes the approved publication model, not Ahmed El-Mangawy's biography, qualifications, ownership of a channel, or expertise.

Optional biography, expertise, affiliation, credential, social-profile, or channel fields are omitted as complete semantic units when absent. Omission means no heading, label, empty element, divider, reserved gap, placeholder, `قريبًا`, or generated filler. Do not expose internal reviewer identities or approval records. Do not render a portrait, avatar, signature, social icon, credential badge, or Person structured data in this phase.

## Responsive and Reflow Contract

- Support the continuous range from `320px` through `1440px`; the only layout breakpoint remains `48rem` and changes padding only.
- Keep one column, the same DOM order, and the same semantic hierarchy at every width. No list becomes a grid, side rail, horizontal scroller, accordion, or carousel.
- Header and main align to the same centered `70ch` measure. New discovery pages may use less than the full measure naturally; do not widen them into a dashboard.
- At `200%` browser zoom, all headings, descriptions, dates, and links reflow without overlap, clipping, or loss of content.
- Require `document.documentElement.scrollWidth <= document.documentElement.clientWidth`; never apply global `overflow-x: hidden` to conceal a defect.
- Give flex/grid children `min-inline-size: 0`. Allow long Arabic titles, mixed fragments, and date labels to wrap.
- Do not use fixed block heights for headers, list items, headings, descriptions, author facts, or empty states.
- Preserve at least the `44px` standalone target for the shared home link and inherited controls. Ordinary linked headings and inline fact links use the inline-link target exception.
- Verification widths are `320`, `390`, `768`, `1024`, and `1440` CSS pixels, plus native `200%` zoom.

## RTL and Bidirectional Contract

- Every route uses `<html lang="ar" dir="rtl">`; no discovery component overrides the ordinary Arabic direction.
- Use `text-align: start` and logical properties. Do not add physical `left`/`right` spacing or positioning declarations.
- Render dates with `<time datetime="YYYY-MM-DD">` and the UTC-stable Arabic long-date formatter inherited from Phase 2. Wrap the visible formatted value in `<bdi dir="auto">` when needed.
- Registry slugs and route URLs stay in `href`; never expose them as visible raw labels.
- An intentionally visible Latin/code/URL fragment must be isolated with the appropriate native element and `<bdi dir="ltr">`. Arabic titles and descriptions remain ordinary RTL text.
- Preserve the Phase 2 rendered-copy guard: reject unisolated Latin prose while allowing intentional `code`/`bdi` content.
- Do not apply tracking, forced LTR, character-level spans, or truncation that could detach Arabic diacritics or corrupt punctuation order.

## Interaction and No-JavaScript Contract

- Discovery and author surfaces require zero client JavaScript. Their complete content and every internal navigation action are present in initial static HTML.
- All links use native same-tab navigation. Do not use `target="_blank"`, click interception, view transitions, prefetch UI, custom keyboard handlers, or client routers.
- Tab follows DOM/document order: shared home link → page-specific section/article/author links → inherited article media controls where present.
- Enter activates each link natively. No Space-key emulation is added to anchors.
- Every focused link shows the inherited `3px` accent outline with `3px` offset; no element clips the outline.
- Hover only thickens the underline. There is no motion, scale, opacity, color-only disclosure, tooltip, or hover-exclusive information.
- With JavaScript disabled, the user can complete homepage → section → article → author → homepage. The existing article remains readable and keeps its permanent direct YouTube action; its enhancement-only player behavior remains governed by Phase 2.
- With CSS unavailable, document headings, lists, facts, dates, and anchors retain a coherent reading and navigation order.

## Accessibility Contract

- Prefer native `header`, `main`, `article`, `section`, headings, `ul`/`li`, `dl`/`dt`/`dd`, `time`, paragraphs, and anchors. Add no ARIA where native semantics already express the relationship.
- Every page has exactly one `main` and one `h1`. Homepage/section article entries use ordered `h2` levels; do not skip heading levels.
- The homepage sections and section articles are real semantic lists. Visual dividers do not replace list semantics.
- Links expose meaningful visible Arabic names. No icon-only link, empty anchor, duplicate hidden name, `aria-label` override, or clickable non-anchor is allowed.
- Keep the header home link accessible name exactly `مدونة أحمد المنجاوي`; keep the author link accessible name exactly `أحمد المنجاوي`.
- All interactive elements participate in native tab order. Do not use positive `tabindex`.
- Preserve visible underlines, `:focus-visible`, contrast thresholds, and the inherited `44px` standalone-control target.
- At 200% zoom and at 320px, no text or control may overlap, clip, require two-dimensional scrolling, or disappear.
- No animation or autoplay is added, so discovery surfaces require no reduced-motion branch.
- Automated checks must report zero serious or critical accessibility violations on the homepage, one populated section index, one representative article, and the author page. Follow with manual landmark, heading, list, accessible-name, focus-visibility, keyboard-order, RTL, and reflow checks.

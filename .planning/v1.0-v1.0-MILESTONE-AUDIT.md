### Additive CMS Publishing Flow

The post-roadmap owner workflow is repository-wired as follows:

```text
Owner → Cloudflare Access → GitHub OAuth Worker → Sveltia
→ cms/* pull request → trusted-base content gate
→ Markdown collection → static build
```

Sveltia defaults new articles to drafts and writes into the existing Markdown collection. The trusted-base pull-request gate restricts CMS changes to direct article files and safe raster media before running the existing checks and static build. This additive flow does not change the original 36-requirement, 13-integration, or 5-flow milestone denominators. Live success remains unclaimed until the owner activates Cloudflare Access, the GitHub OAuth app, protected `main`, and one real draft-only pull request.
